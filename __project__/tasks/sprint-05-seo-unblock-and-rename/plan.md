# Plan: Sprint 05 — SEO unblock + filename rename

## Context

Two threads merge into one sprint because they're cheaper landed together than apart.

**Thread 1 — SEO unblock.** Client sync on 2026-04-27 confirmed the six business facts that were gating Sprint 03's `T302` (per-page metadata) and `T305b` (JSON-LD data wiring): canonical email, phones, operational + MST addresses, neutral 20+ years phrasing, legal-name casing. Confirmed values now live in `brief.md` §3. The sitewide metadata still emits `"Create Next App / Generated by create next app"` — every shared URL preview is a generic blue card. This sprint replaces that with branded text + a static OG image, then wires `Organization` + `LocalBusiness` JSON-LD with the confirmed values.

**Thread 2 — Filename rename.** ADR-005 (2026-04-25) settled kebab-case as the project file naming convention. The implementation chore has been parked in `backlog/ideas.md` for two sprints. Next sprint creates several new files (`src/content/shared/business.ts`, `src/app/opengraph-image.tsx`, …) — landing those on PascalCase only to rename them again in a future cleanup is double work. The rename is mechanical (~19 files, ~46 import sites) and Biome's `useFilenamingConvention` rule will block regression once enabled.

**Ordering principle:** **rename first, SEO second.** The rename is a clean-blame mechanical pass that touches only filenames and imports. Landing it first means every new SEO file in this sprint adopts the convention naturally.
